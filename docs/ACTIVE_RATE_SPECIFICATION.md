# Active率計算機能 仕様書・要件定義書

## 1. 概要

### 1.1 目的
各企業の機能利用状況を定量的に評価するため、Active率を自動計算する機能を実装する。

### 1.2 基本方針
- 各企業の利用開始から3ヶ月間のデータを学習期間として、「利用する機能」を自動抽出
- 学習期間終了後は、抽出された「利用する機能」リストを基準にActive率を計算
- 各機能の利用回数を正規化して、合計が100%になるように計算

## 2. 機能要件

### 2.1 計算対象の機能（16個）

以下の16個の機能の利用回数を使用してActive率を計算する：

| No | 機能名 | 利用ログのカラム名 |
|----|--------|------------------|
| 1 | ログイン | ログイン回数 |
| 2 | 見積作成 | 見積作成数 |
| 3 | 工事登録 | 工事登録数 |
| 4 | 顧客登録 | 顧客登録数 |
| 5 | 業者登録 | 業者登録数 |
| 6 | 請求書作成 | 請求書作成数 |
| 7 | 商品発注書作成 | 商品発注書作成数 |
| 8 | 外注発注書作成 | 外注発注書作成数 |
| 9 | 現場連絡表作成 | 現場連絡表作成数 |
| 10 | 実行予算作成 | 実行予算作成数 |
| 11 | 書類メール送信 | 書類メール送信数 |
| 12 | 資料登録 | 資料登録数 |
| 13 | 写真登録 | 写真登録数 |
| 14 | 工程表作成 | 工程表作成数 |
| 15 | タスク登録 | タスク登録数 |
| 16 | 日報登録 | 日報登録数 |

### 2.2 使用する期間

**現在期間の利用回数を使用する。**

- **週次データの場合**: 対象週の利用回数を使用
- **月次データの場合**: 対象月の利用回数を使用

**例：**
- 対象週: `2026-01-06` → その週（2026-01-06を含む週）の利用回数を使用
- 対象月: `2026-01-06` → その月（2026年1月）の利用回数を使用

### 2.3 学習期間の定義

#### 2.3.1 利用開始日の設定
- 各企業の最初の利用ログの日付を「利用開始日」として自動設定
- `ユーザー基礎情報`テーブルの`usage_start_date`カラムに保存

#### 2.3.2 学習期間
- **期間**: 利用開始日から3ヶ月間
- **目的**: この期間の利用ログを分析して、「利用する機能」を抽出

#### 2.3.3 利用する機能の抽出
- 学習期間中の利用ログを分析
- 各機能について、1回以上使用された機能を「利用する機能」として記録
- `ユーザー基礎情報`テーブルの`used_features`カラム（JSONB型）に保存

**データ形式：**
```json
{
  "features": [
    "ログイン",
    "見積作成",
    "工事登録",
    "顧客登録"
  ],
  "learning_period_end": "2024-04-01",
  "last_updated": "2024-04-01T00:00:00Z"
}
```

## 3. 計算ロジック

### 3.1 Active率の計算方法

#### 3.1.1 学習期間中

**計算方法：**
1. 全16個の機能を基準に計算
2. 現在期間の各機能の利用回数を取得
3. 全機能の利用回数の合計を計算
4. 各機能の利用回数を正規化（合計が100%になるように）

**計算式：**
```
各機能のActive率 = (機能の利用回数 / 全機能の利用回数の合計) × 100
合計Active率 = 各機能のActive率の合計 = 100%
```

**例：**
- ログイン: 100回
- 見積作成: 50回
- 工事登録: 30回
- その他: 0回
- **合計: 180回**

**Active率：**
- ログイン: (100 / 180) × 100 = 55.6%
- 見積作成: (50 / 180) × 100 = 27.8%
- 工事登録: (30 / 180) × 100 = 16.6%
- その他: (0 / 180) × 100 = 0.0%
- **合計: 100.0%**

#### 3.1.2 学習期間終了後

**計算方法：**
1. 「利用する機能」リストを取得（学習期間中に抽出された機能）
2. 「利用する機能」リストに含まれる機能のみを対象に計算
3. 現在期間の各機能の利用回数を取得
4. 「利用する機能」の利用回数の合計を計算
5. 各機能の利用回数を正規化（合計が100%になるように）

**計算式：**
```
各機能のActive率 = (機能の利用回数 / 利用する機能の利用回数の合計) × 100
合計Active率 = 各機能のActive率の合計 = 100%
```

**例：**
- 利用する機能: 10個（ログイン、見積作成、工事登録、顧客登録、業者登録、請求書作成、商品発注書作成、外注発注書作成、現場連絡表作成、実行予算作成）
- 現在期間の利用回数:
  - ログイン: 100回
  - 見積作成: 50回
  - 工事登録: 30回
  - その他: 0回
- **合計: 180回**

**Active率：**
- ログイン: (100 / 180) × 100 = 55.6%
- 見積作成: (50 / 180) × 100 = 27.8%
- 工事登録: (30 / 180) × 100 = 16.6%
- その他: (0 / 180) × 100 = 0.0%
- **合計: 100.0%**

### 3.2 丸め誤差の補正

計算結果の合計が100%にならない場合（丸め誤差）、以下の方法で補正する：

1. 合計と100%の差分を計算
2. 最大の値を持つ機能に差分を追加
3. 合計が100%になるように調整

**例：**
- 計算結果の合計: 99.9%
- 差分: 0.1%
- 最大の値を持つ機能（ログイン: 55.6%）に0.1%を追加
- 調整後: ログイン: 55.7%、合計: 100.0%

### 3.3 スコア計算での使用

計算されたActive率は、スコア計算で使用される。

**スコア計算ロジック：**
- Active率 < 10% → **-15点**
- Active率 > 50% → **+10点**
- それ以外（10%以上50%以下） → **0点**

**注意：**
- スコア計算では、合計Active率（100%）ではなく、「利用する機能」のうち実際に使用した機能の割合を使用
- 使用した機能の割合 = (使用した機能数 / 利用する機能数) × 100

**例：**
- 利用する機能: 10個
- 現在期間で使用した機能: 3個（ログイン、見積作成、工事登録）
- 使用した機能の割合 = (3 / 10) × 100 = 30%
- スコア計算: 30%は10%以上50%以下なので、**0点**

## 4. データベース構造

### 4.1 ユーザー基礎情報テーブル

**追加カラム：**

| カラム名 | データ型 | 説明 |
|---------|---------|------|
| `usage_start_date` | DATE | 企業の利用開始日（最初の利用ログの日付） |
| `used_features` | JSONB | 利用開始から3ヶ月間で使用された機能のリスト |

**`used_features`のデータ形式：**
```json
{
  "features": [
    "ログイン",
    "見積作成",
    "工事登録"
  ],
  "learning_period_end": "2024-04-01",
  "last_updated": "2024-04-01T00:00:00Z"
}
```

### 4.2 usage_logsテーブル

**既存カラム：**
- `Active率`: TEXT型（計算されたActive率を保存）

**追加カラム（将来の拡張用）：**
- `feature_usage`: JSONB型（各機能の利用状況を詳細に記録）

## 5. 処理フロー

### 5.1 インポート時の処理

1. **利用ログの保存**
   - Excel/CSVファイルから利用ログデータを取得
   - 各機能の利用回数を取得（16個の機能）

2. **利用開始日の設定**
   - 初回インポート時、利用開始日が設定されていない場合
   - 現在の期間日を利用開始日として設定

3. **Active率の計算**
   - 現在期間の利用ログから各機能の利用回数を取得
   - 学習期間中かどうかを判定
   - Active率を計算
   - 計算結果を`usage_logs`テーブルの`Active率`カラムに保存

4. **利用する機能の更新**
   - 学習期間終了後、自動的に「利用する機能」を抽出
   - `used_features`カラムに保存

### 5.2 スコア計算時の処理

1. **利用ログの取得**
   - 現在期間の利用ログを取得
   - 前期間の利用ログを取得（比較用）

2. **Active率の取得**
   - 利用ログの`Active率`カラムから取得
   - 未計算の場合は、自動計算を実行

3. **スコア計算**
   - Active率に基づいて変動値を計算
   - 最終スコアを計算

**現在期間の利用回数：**

- 見積作成: 50回
- 工事登録: 30回
- その他: 0回

**計算：**
1. 全機能の利用回数の合計: 180回

   - その他: (0 / 180) × 100 = 0.0%

## 7. エッジケース

### 7.1 利用回数がすべて0の場合

**処理：**
- すべての機能のActive率を0%とする
- 合計: 0%（100%にはならない）
- スコア変動値: -15点（Active率 < 10%）

### 7.2 利用する機能が1つのみの場合

**処理：**
- その機能のActive率を100%とする
- 合計: 100%
- スコア変動値: +10点（Active率 > 50%）

### 7.3 学習期間中に利用ログがない場合

**処理：**
- 利用開始日は設定されるが、「利用する機能」は空のリストになる
- 学習期間終了後も、全機能を基準に計算を続行

### 7.4 利用開始日が設定されていない場合

**処理：**
- 最初の利用ログの日付を利用開始日として自動設定
- その後、通常の処理フローに従う

## 8. 非機能要件

### 8.1 パフォーマンス
- Active率の計算は、インポート時とスコア計算時に実行
- 計算時間は1企業あたり100ms以内を目標

### 8.2 データ整合性
- 利用開始日は、最初の利用ログの日付と一致すること
- 「利用する機能」は、学習期間中の利用ログから正確に抽出されること

### 8.3 エラーハンドリング
- 利用ログが存在しない場合、Active率は0%とする
- 計算エラーが発生した場合、警告をログに記録し、処理を続行

## 11. スコア計算ロジックとの統合

### 11.1 スコア計算の全体フロー

1. **利用ログの取得**
   - 現在期間の利用ログを取得
   - 前期間の利用ログを取得（比較用）

2. **Active率の計算**
   - 現在期間の利用ログからActive率を計算
   - 計算結果をスコア計算に使用

3. **基本変動値の計算**
   - ログインなし: -40点
   - 見積未利用: -15点
   - 工事未利用: -15点
   - Active率 < 10%: -15点
   - Active率 > 50%: +10点
   - トレンド（前期間比）: -10点 または +10点

4. **インパクト係数の適用**
   - 月額契約額（MRC）≥ 55,000円の場合、変動値合計を1.5倍に増幅

5. **最終スコアの計算**
   - 最終スコア = max(0, min(100, 100 + (変動値合計 × インパクト係数)))

### 11.2 Active率とスコア計算の関係

**Active率の計算：**
- 各機能の利用回数を正規化して、合計が100%になるように計算

**スコア計算での使用：**
- 合計Active率（100%）ではなく、「利用する機能」のうち実際に使用した機能の割合を使用
- 使用した機能の割合 = (使用した機能数 / 利用する機能数) × 100

**例：**
- 利用する機能: 10個
- 現在期間で使用した機能: 3個
- 使用した機能の割合: (3 / 10) × 100 = 30%
- スコア変動値: 0点（10%以上50%以下）
